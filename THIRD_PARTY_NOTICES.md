# Publisher attribution and third-party content

CyberWatch preserves publisher names, original URLs, original publication dates and available image credits. A publisher's name in the source catalogue does not mean that the publisher sponsors this project or guarantees feed availability.

General news sources default to feed excerpts and original links. Enabling a source's full-text policy is an administrator decision that requires the relevant reuse permission. Source material retains its own license; the inclusion of a project source archive does not relicense publisher articles or images.

## GitLab documentation and security releases

The bundled GitLab security source links to the official documentation release pages at <https://docs.gitlab.com/releases/>. GitLab documentation identifies its content license as [Creative Commons Attribution-ShareAlike 4.0 International](https://creativecommons.org/licenses/by-sa/4.0/), with evidence in the [official documentation footer](https://docs.gitlab.com/development/documentation/).

Attribution: GitLab and the respective documentation contributors. Each collected entry links to its specific original release page. The reader converts publisher formatting to plain text, removes navigation and unrelated page elements, and labels any shortened content as an excerpt. Collected GitLab documentation and adaptations of that documentation remain subject to CC BY-SA 4.0. Image rights can differ; preserve supplied credits and confirm reuse rights for any additional redistribution.

## Displaying notices on a static deployment

The reader's source note carries the configured license/attribution alongside the original link. This complete notice is distributed with the project and is also available as `dist/third-party-notices.txt` in published installations. Additional full-text sources should carry their required attribution and license terms in the source policy and this notice before enabling redistribution.
